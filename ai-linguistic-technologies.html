AI & Linguistic Technologies

Language quality depends on more than whether an individual sentence reads well. Meaning can shift with context, register, terminology, source evidence, interface constraints or the relationship between one piece of content and the next. I apply that same systems-level perspective when building AI instructions and workflow tools.

Instruction architecture & prompt design

I organize instructions into reusable rules, reference files, task-specific templates and conditional pathways. The goal is to make requirements explicit: what the system should do, which sources it must use, what it must not infer, and how the result should be structured.

AI-assisted writing & voice systems

I develop structured AI workflows that account for voice, register, tone, format and context. These systems can help make editorial conventions reusable across content types while keeping a human author or editor responsible for the final text.

Language quality & evaluation foundations

My professional background includes comparative revision, terminology control, guideline-based review, post-editing and linguistic QA. These skills provide a practical foundation for examining language outputs for accuracy, consistency, register, context and compliance with explicit criteria.

Workflow automation & structured information

I build and explore workflows that extract content, organize records, connect applications through APIs and move information between systems. Where interpretation is uncertain, human review remains an important control rather than an afterthought.

Technical implementation

My applied toolkit includes HTML/CSS, JavaScript, Python, Google Apps Script, REST APIs, Make and document automation. I use these technologies to support practical workflows and investigate how language, data and software components fit together.

Selected independent projects

The projects below illustrate applied problem-solving and ongoing technical practice. They are independent or internal projects, not evidence of a history of commercial AI-model evaluation assignments.

Custom AI Skill — Literary Voice Modeling

A modular instruction system designed to guide an AI through five distinct writing registers. It combines a central skill file with specialized references, explicit stylistic constraints, safeguards against unsupported personal details, and a repeatable content-production workflow. The author retains final editorial approval. Iterative tests have been qualitative; no controlled benchmark or quantified improvement is claimed.

LLM Prompt Engineering & Logic Routing →

A source-grounded analytical workflow that classifies a case against a project-specific reference matrix and routes the task to a suitable template. Explicit evidence requirements and task-specific structures help reduce generic responses and make required sections easier to verify. This is a literary and analytical workflow, not a clinically validated diagnostic system.

Drive-to-Notion Migration Pipeline →

A Google Apps Script workflow that extracts text from supported document formats, creates structured Notion pages, preserves links to source files and uses batch processing and execution logs to manage runtime constraints. Images were retained as attachments or references; OCR was not part of the documented workflow. The pipeline was used operationally, with some historical errors documented in its logs.

DataBerry Nexus — Gmail Workflow Automation →

A Google Workspace application connecting email categorization, document archiving, PDF generation and structured contact records. Several components have been demonstrated, while full end-to-end validation remains pending. Planned capabilities are not presented as completed features.

Plugin Pilot — Structured Plugin Review

An Obsidian-oriented project for organizing plugin information through categories, metadata and review fields. It demonstrates taxonomy and information-structuring practices; it is not an AI model or a production model-evaluation system.

A method built around context and control

  1. Define the task and constraints — Clarify the intended use, audience, source material, required output and boundaries.
  2. Structure the instructions — Separate reusable rules, reference material, terminology, routing logic and task-specific templates.
  3. Make evidence requirements explicit — Specify what must be checked against source material and where unsupported inference must be avoided.
  4. Review the output in context — Check the result against the criteria and retain human review wherever judgment or interpretation matters.
