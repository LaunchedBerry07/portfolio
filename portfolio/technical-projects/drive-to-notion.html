Drive-to-Notion Migration Pipeline

Automating large-scale document migration while preserving source traceability

Google Apps Script Google Drive API Notion API Google Sheets

Project overview

Moving a large document collection from Google Drive into Notion involves more than copying files. Content must be extracted from different formats, organized into usable pages, linked back to its source, and processed within the execution limits of the services involved.

I designed and used an automated Google Apps Script pipeline to accelerate this migration. The workflow retrieves source documents, extracts supported text, creates structured Notion pages with links to the original Drive files, and moves processed files into a separate folder for later classification. Batch processing, timed resumption and execution logs help the workflow continue across multiple runs and make failures easier to investigate.

The challenge: scale, formats and execution limits

The source collection contained a substantial volume of documents, while the destination required content to be represented as structured Notion pages rather than as an undifferentiated file dump. The pipeline also had to accommodate differences between file formats, Notion’s page and property requirements, and Google Apps Script’s limited execution window.

The practical challenge was to make migration repeatable without losing the connection between each migrated record and its original file. Processing everything in a single execution was not a viable approach, so the workflow needed to divide work into manageable batches and resume automatically.

From source files to structured Notion pages

The pipeline uses Google Apps Script to coordinate the migration through the Google Drive and Notion APIs. Its documented workflow consists of several connected stages:

1

Retrieve source documents from designated Google Drive locations.

2

Extract text from supported formats, including PDF and DOCX; some files were temporarily converted to Google Docs to make extraction possible.

3

Create structured Notion pages and preserve a direct reference to each original Drive file.

4

Move processed source files to a separate Drive folder so they can be classified later.

5

Process items in batches, resume after a timed pause, and record execution details in Google Sheets for troubleshooting.

Managing interruptions and errors

Because a migration of this scale cannot depend on one uninterrupted script run, the workflow uses batch processing and timed resumption to work within Apps Script’s execution constraints. Google Sheets logs provide a record of execution activity and help identify API or data-validation issues that require attention.

The logs documented Notion API validation errors, including cases where a filename exceeded a 100-character property limit. They support troubleshooting, but do not establish that every historical error was eliminated. Duplicate detection was not part of the pipeline’s documented scope.

A related migration, kept separate

A separate script was used to migrate legacy nested Notion pages into a database-based structure. That work addressed an existing Notion information architecture; it was not a stage of the Google Drive file-migration pipeline. Keeping the two workflows distinct makes the scope and responsibilities of each process clearer.

Scope and limitations

The pipeline was used operationally for approximately eight months and reportedly processed tens of thousands of files representing multiple gigabytes. These figures are based on user-reported experience and have not been independently audited.

PNG and JPG images were retained as attachments or references; optical character recognition (OCR) was not part of the documented workflow. The pipeline was designed to extract supported document content and create linked Notion records, not to interpret every file type or guarantee a fully classified destination library. Processed files were moved to a separate folder for later classification, and duplicate detection remained outside scope.

What the project demonstrates

  • Designing an API-connected workflow across Google Drive, Notion and Google Sheets.
  • Extracting and structuring content from supported document formats.
  • Preserving source traceability through links to original files.
  • Managing large workloads through batching and timed resumption.
  • Using execution logs to investigate API validation and data-quality issues.
  • Defining system boundaries clearly, including unsupported image OCR and duplicate detection.
The bottom line!

The takeaway

Reliable migration is not simply a matter of moving files. It requires content extraction, structured destination records, source traceability and execution management designed around real platform constraints.
